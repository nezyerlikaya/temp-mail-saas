# v1.1 Inbox Experience Planning

STEP62 adds a planning-only foundation for the v1.1 inbox and mailbox experience roadmap. It does not redesign the inbox, add frontend components, or change public mailbox behavior.

## Inbox Review Model

The inbox review checks aggregate readiness signals only:

- Inbox route availability and usability readiness
- Message list and detail visibility readiness
- Polling experience readiness
- Mailbox discoverability readiness

The review states are:

- `excellent`
- `acceptable`
- `improvement-needed`

## Mailbox Lifecycle Model

Mailbox lifecycle planning reviews:

- Mailbox creation flow
- Mailbox usage flow
- Expiration defaults
- Cleanup readiness

The review uses existing route and retention configuration signals without reading mailbox contents.

## Message Workflow Model

Message workflow planning reviews:

- Message arrival foundations
- Message reading route readiness
- Attachment metadata foundation
- Retention defaults

The service checks schema and configuration readiness only. It does not inspect payloads, message bodies, mailbox addresses, or attachment files.

## Accessibility Model

Inbox accessibility planning reviews:

- Keyboard navigation readiness
- Screen reader readiness
- Color contrast readiness
- Responsive experience readiness

These checks are configuration-driven so future v1.1 implementation can tighten criteria without changing the public inbox.

## UX Prioritization Methodology

UX candidates are defined in `config/inbox-roadmap.php` and classified by:

- Priority
- Impact
- Complexity
- Risk

The prioritization service produces:

- Quick wins
- High-impact improvements
- Low-risk improvements
- Deferred candidates

## Recommended v1.1 Inbox Improvements

The initial recommended planning candidates are:

- Clarify mailbox lifecycle states
- Improve message arrival feedback
- Run a focused inbox accessibility pass
- Plan attachment workflow affordances
- Define polling expectation improvements

## Operational Notes

The roadmap command is:

```bash
php artisan system:inbox-roadmap-status
```

It emits safe aggregate output only. No mailbox contents, message bodies, email addresses, DNS values, provider secrets, or payloads are logged.
