# v1.1 Feature Candidates

STEP61 prepares concrete v1.1 feature candidate planning without implementing v1.1 features or adding roadmap UI.

## Candidate Model

- Candidates store UUID, title, optional description, category, priority, status, effort, impact, risk, and sanitized metadata.
- Categories include inbox, billing, admin, API, automation, enterprise, growth, operations, and platform.
- Status moves through proposed, reviewed, accepted, deferred, or rejected.

## Prioritization Method

- Candidate score compares priority and impact against effort and risk.
- Low-effort, low-risk, high-impact candidates become quick-win candidates.
- High-risk and critical-risk candidates require explicit review before implementation.

## Release Planning Method

- Accepted candidates are grouped into v1.1 release phases.
- Quick wins are separated for early execution planning.
- Deferred candidates remain tracked but outside the first v1.1 implementation pass.

## Implementation Readiness Model

- Review dependencies.
- Review test readiness.
- Review documentation readiness.
- Review operational readiness.
- Block critical-risk candidates when configured.

## Recommended First v1.1 Candidates

- Inbox UX and mailbox experience planning.
- Aggregate-only product analytics storage design.
- Readiness service consolidation review.
- Operational runbook maintenance cadence.
