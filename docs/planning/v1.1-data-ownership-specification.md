# v1.1 Data Ownership Specification

## Scope

STEP68 is specification-only. It does not add migrations, models, tenant isolation, organization implementation, permission changes, auth changes, billing changes, queue changes, or mailbox changes.

## Ownership Domains

### Personal Ownership

The resource is fully owned by a single user.

Examples:

- Personal mailbox
- Personal API key
- Personal settings

### Organization Ownership

The resource is owned by the organization as an enterprise boundary.

Examples:

- Organization domains
- Organization reports
- Organization audit logs

### Shared Ownership

The resource has layered access across user, organization, workspace, team, and delegated roles.

Examples:

- Workspace reports
- Team resources
- Shared mailboxes

## Resource Ownership Principles

- Ownership defines accountability.
- Visibility must be narrower than ownership.
- Export must require explicit policy.
- Deletion must respect retention, audit, and legal hold needs.
- Personal data and organization operational data must be separable.

## Future API Ownership Model

- User API Key: owned by a single user and scoped to personal resources.
- Organization API Key: owned by an organization and controlled by policy.
- Workspace API Key: owned by a workspace and scoped to workspace resources.
- Service API Key: owned by an organization service account with strict lifecycle controls.
