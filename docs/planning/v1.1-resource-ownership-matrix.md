# v1.1 Resource Ownership Matrix

## Scope

This matrix is a future policy reference. It does not change ownership of any current production resource.

| Resource | Future Owner | Visibility Boundary |
| --- | --- | --- |
| Mailboxes | Personal or Organization | Owner and scoped admins |
| Domains | Organization | Owner, organization admin, security admin |
| Domain Pools | Organization or Platform | Platform and organization admins |
| Messages | Mailbox owner | Mailbox owner and policy-scoped roles |
| Attachments | Message owner | Message owner and policy-scoped roles |
| API Keys | User, Organization, Workspace, or Service | Key owner and security admin |
| Audit Logs | Organization or Platform | Owner, admin, security, compliance roles |
| Security Events | Organization or Platform | Security roles and owner |
| Reports | Organization or Workspace | Report owner and scoped admins |
| Analytics | Organization or Platform | Aggregate-only authorized roles |
| Billing Resources | Organization or User | Owner and billing admin |
| Organization Settings | Organization | Owner and organization admin |
| Workspace Resources | Workspace | Workspace admin and scoped members |
| Team Resources | Team | Team lead and scoped members |

## Isolation Notes

- Soft isolation is low cost but weak.
- Logical isolation is the likely SaaS default.
- Tenant isolation improves separation but increases cost.
- Dedicated resource isolation should be enterprise-only.
