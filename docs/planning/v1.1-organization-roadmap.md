# v1.1 Organization Roadmap

## Roadmap Principle

The organization roadmap must remain non-breaking. Future implementation should extend the current user, billing, RBAC, mailbox, domain, security, and automation foundations without replacing them.

## Phase 1: Domain Model Specification

- Define Organization, Workspace, Team, and Membership entities.
- Define ownership boundaries for domains, mailboxes, API keys, billing, and audit events.
- Define organization role vocabulary without replacing staff RBAC.
- Write tenancy decision records before schema work.

## Phase 2: Delegated Administration Planning

- Owner: full organization authority.
- Organization Admin: daily account management.
- Workspace Admin: scoped workspace administration.
- Team Lead: team management.
- Member: standard access.
- Guest: restricted access.

## Phase 3: Organization Billing Planning

### Seat Based Billing

Best for predictable team pricing. Requires seat lifecycle, invitations, removals, and proration rules.

### Workspace Billing

Useful for agencies and department-heavy customers. Can become hard to explain if customers create many workspaces.

### Usage Billing

Useful for mailbox, domain, API, and retention usage. Requires strong metering and transparent cost controls.

### Hybrid Billing

Best long-term fit: seats plus usage controls. It has the highest operational complexity and needs guardrails.

## Phase 4: Enterprise Governance Planning

- Access governance
- Organization policy management
- Compliance readiness
- Audit readiness
- Data retention governance
- Organization security controls

## Phase 5: Enterprise Security Planning

- SSO readiness
- SAML readiness
- OIDC readiness
- Enterprise MFA policy
- Device policies
- Session governance
- Access reviews
- Organization audit trails
- Delegated security administration

## Phase 6: Enterprise Operations Planning

- Organization dashboard
- Team activity monitoring
- Organization audit center
- Organization security center
- Compliance dashboard
- Usage analytics
- Cost analytics

## Recommended STEP67

STEP67 should define the v1.1 Enterprise & Organization Domain Model Specification. It should produce non-breaking entity definitions, ownership rules, tenancy decision records, and implementation guardrails before any migration exists.
