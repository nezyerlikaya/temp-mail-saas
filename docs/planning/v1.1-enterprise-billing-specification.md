# v1.1 Enterprise Billing Specification

## Purpose

STEP74 defines future enterprise billing architecture for Temp Mail SaaS v1.1. This is planning-only. It does not change the current Free, Member, or Premium plan model and does not implement seats, payment providers, organization billing, migrations, queues, or events.

## Billing Domains

Future billing should distinguish personal billing, team billing, organization billing, and enterprise contract billing.

Personal billing remains user-owned and simple. Team billing introduces shared cost visibility and delegated billing review. Organization billing introduces organization-level subscriptions, approval boundaries, seat governance, and usage governance. Enterprise contract billing introduces procurement, contract ownership, renewal review, suspension readiness, and termination rules.

## Domain Boundaries

Each billing domain should define owner, controller, reviewer, escalation owner, resource scope, evidence requirements, and audit expectations before implementation.

## Existing System Compatibility

The current plan system remains the foundation for Free, Member, and Premium differentiation. Future enterprise billing should extend that foundation by adding ownership and governance layers around organizations, contracts, seats, and usage without replacing the existing plan assignment model.

## Future Architecture Recommendation

The safest path is to define enterprise billing as a governance overlay first: ownership, approval, audit evidence, reporting, and cost visibility before any checkout or payment-provider activation.

## Non-Implementation Boundary

No billing provider, checkout flow, invoice system, seat system, contract table, or organization billing behavior is implemented by this step.
