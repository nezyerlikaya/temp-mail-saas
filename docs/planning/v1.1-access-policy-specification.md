# v1.1 Access Policy Specification

## Scope

This document specifies future access policy concepts only. No permissions, middleware, guards, roles, or access checks are implemented in STEP68.

## Access Policy Types

### Direct Access

Explicit access granted to a user, member, role, or service.

### Inherited Access

Access inherited from organization, workspace, team, or role membership.

### Delegated Access

Scoped access delegated by an owner or admin for defined responsibilities.

### Temporary Access

Time-bound access for support, incident, audit, contractor, or onboarding workflows.

### Emergency Access

Break-glass access with strict audit, approval, expiry, and review requirements.

## Visibility Policy Model

- Owner: all organization resources, billing, audit summary, security summary.
- Organization Admin: members, workspaces, teams, reports, operational summary.
- Workspace Admin: workspace resources, workspace members, workspace reports.
- Team Lead: team resources, team members, team activity summary.
- Member: assigned resources, own activity, permitted reports.
- Guest: explicitly shared resources.

## Delegated Access Roles

- Temporary Admin
- Security Reviewer
- Compliance Reviewer
- Billing Reviewer
- External Auditor
