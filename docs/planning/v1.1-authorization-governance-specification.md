# v1.1 Authorization Governance Specification

## Scope

STEP72 is specification-only. It does not implement permissions, roles, auth changes, billing changes, organizations, tenants, migrations, queues, events, or data writes.

## Authorization Domains

### Authentication

Verifies identity. It must remain separate from authorization decisions.

### Authorization

Decides what authenticated identities may do.

### Delegated Authorization

Allows scoped authority granted by eligible owners or administrators.

### Privileged Authorization

Governs high-impact administrative access.

### Emergency Authorization

Break-glass access with expiry, reason, and audit requirements.

### Service Authorization

Authorizes non-human service, API, automation, and integration identities.

## Future Policy Enforcement Readiness

- Policy Based Authorization
- Context Aware Authorization
- Risk Based Authorization
- Attribute Based Authorization
- Enterprise Governance Policies

No enforcement is implemented in STEP72.
