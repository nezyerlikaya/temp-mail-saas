# v1.1 Enterprise Domain Model Specification

## Scope

STEP67 is specification-only. It does not implement organizations, teams, workspaces, memberships, tenancy, billing changes, authentication changes, permission changes, migrations, events, or queues.

## Organization Domain

Future entity: `Organization`

Example future fields:

- `name`
- `slug`
- `status`
- `owner`
- `settings`
- `security_profile`

Purpose: top-level customer-owned business boundary for future startup, agency, corporate, and enterprise customers.

Status: specification-only.

## Workspace Domain

Future entity: `Workspace`

Examples:

- Marketing
- Operations
- Security
- Development

Future responsibilities:

- Scoped ownership inside an organization
- Isolation boundary for resources and policies
- Department or business-unit grouping
- Future delegated administration boundary

Status: specification-only.

## Team Domain

Future entity: `Team`

Examples:

- Moderation
- Support
- Infrastructure
- Compliance

Future responsibilities:

- People grouping
- Workflow ownership
- Review and escalation routing
- Team-level permission assignment

Status: specification-only.

## Organization Role Model

- Organization Owner: full organization, billing, security, and lifecycle authority.
- Organization Admin: daily organization management without ultimate ownership transfer authority.
- Workspace Admin: scoped workspace administration.
- Team Lead: team membership coordination and workflow oversight.
- Member: standard assigned access.
- Guest: restricted or temporary access.

## Seat Management Model

Future seat states:

- Assigned Seat
- Unassigned Seat
- Reserved Seat
- Suspended Seat

Seats should be treated as billing and capacity units, not identity records.

## Organization Billing Domain

Seat-based billing is the best first enterprise primitive because it maps cleanly to membership.

Usage-based billing is useful for mailbox, domain, API, and retention limits after metering matures.

Hybrid billing is the recommended long-term model: seats plus controlled usage.

## Resource Ownership Model

Future organization-owned resources may include:

- Mailboxes
- Domains
- API Keys
- Audit Logs
- Reports
- Billing Resources

## Domain Events Specification

Future domain events may include:

- OrganizationCreated
- MemberInvited
- SeatAssigned
- WorkspaceCreated
- TeamCreated
- OrganizationSuspended

These are documentation-only. No events are implemented in STEP67.

## Future API Domain Analysis

Future API areas may include:

- Organization API
- Workspace API
- Membership API
- Team API
- Governance API
- Audit API

No endpoints are implemented in STEP67.
