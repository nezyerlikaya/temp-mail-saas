# v1.1 Technical Debt Review

## Low Priority Debt

- Expand documentation cross-links between planning reports.
- Standardize future roadmap score terminology across optional editions.

## Medium Priority Debt

- Define API lifecycle and documentation implementation plan.
- Convert future observability dashboard specifications into phased delivery candidates.

## High Priority Debt

- Do not start tenant implementation before ownership and access boundaries are approved.
- Do not activate enterprise billing before seat, contract, evidence, and rollback governance are designed in implementation detail.

## Architectural Risks

- Premature tenant implementation could complicate current stable personal-account behavior.
- Enterprise features could create authorization drift without centralized policy enforcement.
- Billing, ownership, and tenant scope could become entangled if delivered in one release.

## Operational Risks

- Enterprise onboarding without evidence workflows would weaken auditability.
- Seat or usage billing without cost visibility would create customer trust risk.
- External monitoring integration without redaction governance could expose sensitive data.

## Recommended Handling

Keep current production behavior stable. Open a new roadmap before implementation work and split tenant, organization, identity, governance, and commercial work into separate release gates.
